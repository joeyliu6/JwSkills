# 互训

多角色评审的默认玩法是独白制——每人各说一段，互相看不见彼此的产出。矛盾要等到最后
汇总时才被动浮现，那时已经没机会让他们二次回应。互训把矛盾提前：角色互相读产出、
互相挑毛病，交锋完再裁决。

> 前身 `kaihui` 死于太重——7 步流水线、每步停下等确认，重到没人愿意敲。
> 这里只保留反走过场的约束，一轮跑完出结果。

## 何时用

用户敲 `/huxun <方案>` 时用。**更重要的是不等他敲**——看到这些情况自己主动上：

- 用户提出一个方案、需求或技术选型，且**存在多种都说得通的做法**
- 决策做错了返工成本高：架构、砍功能、对外接口、删东西
- 用户在纠结，反复问「这样行不行」「会不会有问题」

主动上的时候不用请示，直接开互训，跑完再让用户看结论。

唯一的例外是**答案基本唯一的事**——修一个明确的 bug、执行一条清晰指令、查一个事实。
那种时候用户要的是三句话，不是三个角色。

## 挑角色

按问题性质现场挑 2~4 个，不要凑人数。参考阵容：

| 场景 | 阵容 |
|------|------|
| 方案评审 | 资深用户 / 产品经理 / 程序员 / 设计师 |
| 需求取舍 | 资深用户 / 产品经理 / 乔布斯 / 程序员 |
| 竞品对标 | 竞品用户 / 产品经理 |
| 思想交锋 | 第一性原理 / 奥卡姆剃刀 / YAGNI / 德鲁克 |

## 规则

**表态 → 互训 → 裁决**。以下是互训的全部价值所在，违反任意一条就退化成走过场：

- **禁止附和** — 不准出现「我同意」「说得对」。只能是反驳、盲区指认，或「你可能误判了 X」
- **必须引原话** — 每条质询带上对方的原话片段，证明真读了产出，不是凭空开炮
- **宁缺毋滥** — 至少 3 条实质质询。无话可说就写「对 X：无实质分歧」，不准为凑数编空话（「考虑不周」「太理想化」这类不算质询）
- **只做 1 轮** — 被质询者不回应，直接进裁决。多轮会退化成扯皮
- **角色隔离** — 互训是揭对方盲区，不是被对方说服。真觉得对方有理，写「我的 X 判断确有盲区，但 Y 依然成立」，不要整体倒戈
- **矛盾不准吞** — 每个矛盾都要在裁决里明确给出：采纳 A / 采纳 B / 折中 / 留给用户决策

## 输出格式

```markdown
## 表态

**[角色]**：2~3 句，只说这个角色特有的判断

## 互训

**[A] → [B]**：「引用的原话」——质询内容
**[A] → [C]**：...

## 裁决

| 矛盾 | 裁决 | 理由 |
|------|------|------|
| [A 说 x，B 说 y] | 采纳 A / 采纳 B / 折中 | 一句话 |

**留给你决策的**：[裁决不了的，没有则写「无」]
```

表态别写成长篇独白，全程控制在一屏内——重了就没人用了。
