# /summon — 召唤词调度器

> 一个名词 = 一整套思想的压缩包。AI 听到名字就能激活整套方法论，比几千字的描述更有效。

## 快速上手

把这三个文件放到你的 Claude Code skills 目录：

```bash
# 用户级（所有项目共享）
cp -r summon/ ~/.claude/skills/

# 或项目级
cp -r summon/ /path/to/your-project/.claude/skills/
```

然后在 Claude Code 里：

```
/summon 帮我设计一个设置页面，别太花哨
```

AI 会自动挑出匹配的召唤词并宣告：

```
🎖 已召唤：
   · Dieter Rams 十诫（克制功能优先）
   · 原研哉的"白"（留白极简）
   · [避雷] 不要硅谷独角兽 landing page 风
开始执行...
```

## 三种使用方式

| 方式 | 示例 | 说明 |
|------|------|------|
| A. 自动匹配 | `/summon 帮我选数据库方案` | AI 按需求自动挑词 |
| B. 手动指定 | `/summon 第一性原理 奥卡姆剃刀 \| 帮我选数据库方案` | 管道符前指定词 |
| C. 查看词典 | `/summon --list` | 列出全部 20 词 + 7 避雷 |

## 词典范围

- **20 个正向召唤词**（见 [dictionary.md](dictionary.md)）：分决策/设计/工程/调试/写作 5 组
- **7 条避雷区**（见 [avoid-list.md](avoid-list.md)）：告诉 AI 什么不要

## 什么时候用 summon 效果最好

经过对比测试（见 [tests/summon-eval/](../../tests/summon-eval/)），summon 的效果取决于**任务发散度**和**模型能力**：

| 场景 | summon 增量 | 说明 |
|------|------------|------|
| 复杂写作（品牌文案、博客、README） | 大 | 方向选择多，召唤词帮 AI 选你要的风格 |
| 规划与反思（技术债清理、架构回顾） | 大 | 策略发散，召唤词帮 AI 做取舍判断 |
| 设计与体验（UI 改进、交互优化） | 大 | 美学方向发散，召唤词指定品味 |
| 简单技术问答（排查 bug、写 PR） | 小 | 答案收敛，好模型默认就做得好 |
| 琐碎任务（一行代码、格式转换） | 无 | 不会触发，已设置退出规则 |

> **一句话**：任务越"怎么做都行"的时候，summon 越有用。任务越"就一个标准答案"的时候，summon 越多余。

## 核心心法

1. **少即是多** — 3 个精准名词 > 30 个模糊形容词
2. **单次最多 3 正 + 2 避雷** — 同时喊 10 个哲学家，AI 会精神分裂
3. **宣告先行** — AI 必须先告诉你召唤了什么，再开始执行
4. **警惕冲突互斥** — "KISS"和"企业级架构"不能同时召唤

## 建自己的私人词典

**这才是 summon 真正的玩法**。

词典不是标准答案，是**你个人品味的投射**。建议：

1. Fork 这个仓库
2. 修改 `dictionary.md` — 换上你自己收藏的思想家/方法论
3. 修改 `avoid-list.md` — 写下你最讨厌的那几种风格
4. 一两周后回顾：哪些词高频使用？哪些没用过？迭代到 30-50 词的稳定版本

## 好召唤词的四个标准

| 标准 | 说明 | 反例 |
|------|------|------|
| **高知名度** | AI 训练语料中出现频繁 | "我同事老王的编码规范" |
| **高浓度** | 一个词 = 一整套方法论 | "好代码"（太泛） |
| **语义收敛** | 不同人理解基本一致 | "优雅"（每人定义不同） |
| **可验证** | 能判断输出是否符合 | "有灵魂的设计"（玄学） |

**自测方法**：念出名字，如果脑子里能立刻蹦出 3 条具体规则，它就是好召唤词。
