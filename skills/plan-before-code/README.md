# Plan Before Code — 先设计后编码

> AI 越强，设计阶段越重要。实现变便宜之后，错误的设计带来的返工成本才是主要成本。

## 快速开始

1. 把 `plan-before-code/` 文件夹复制到你项目的 `.claude/skills/` 目录
2. 使用：`/plan-before-code 实现用户注册功能，包含邮箱验证和 OAuth 登录`

## 它做什么

在 AI 写任何代码之前，强制完成三阶段设计：

| 阶段 | 产出 | 你审核什么 |
|------|------|-----------|
| Phase 1：架构骨架 | 模块拆分 + 数据结构 + Mermaid 依赖图 | 模块划分合理吗？有遗漏吗？ |
| Phase 2：流程与状态 | Mermaid 流程图 + 状态机 | 异常路径都覆盖了吗？ |
| Phase 3：边界清单 | 7 个方向的边界场景表 | 有没有漏掉的边界？ |

每个阶段你确认后才进入下一阶段。三阶段通过后，输出合并的设计文档 + 实现计划。

## 为什么有效

**改流程图一行字 = 改代码半小时。**

AI 默认行为是拿到需求就开始写——一个文件写到底，只走 happy path。这个 skill 强制它先想清楚再动手，把问题暴露在成本最低的阶段。

核心洞察：流程图本身也会漏边界（AI 画的流程图也只有它想到的东西）。所以 Phase 3 的边界清单按 7 个方向强制枚举：中断、空值、错误、并发、规模、跨功能、状态转换。

## 何时使用

- 新功能开发（尤其是多模块）
- 从零开始的项目或模块
- 涉及新数据模型的任务
- 跨前后端的功能

## 何时不使用

- Bug 修复、单文件改动
- 重构现有代码
- 探索/原型、需求不清楚
- 样式/CSS 调整

## 与其他 skill 配合

```
/summon（定方向）→ /plan-before-code（做设计）→ /triple-check（逐模块实现）→ /code-review（最终审查）
```

设计文档的实现计划会列出模块顺序，可以直接逐个交给 `/triple-check` 高质量实现。
