# 模板

照抄，按项目实际改。**每一段都要问一句：不写这段，AI 会做出错误假设或找不到东西吗？**
答不上来就删掉——写了也是噪音，还稀释真正重要的信息。

---

## 1. CLAUDE.md：AI 工作方式

必装。三条挨着写，顺序别调——第三条是前两条的边界，
单独给自主权而不给边界，AI 最典型的越界就是顺手加一层用不上的抽象。

```markdown
## AI 工作方式

**一次做完**：连续执行到任务完成，不做一半停下汇报进度。

**只有这五类事停下问我**（清单外的工程选择自己定，把依据写进产出）：

1. 改变产品范围或目标用户
2. 改变主要技术栈、公开 API 或长期数据格式
3. 改变安全、隐私、认证或许可边界
4. 不可逆操作：删数据、改 git 历史、迁移
5. 需要花钱、密钥或生产权限

**自主权只用于减少提问，不用于扩大范围**：不加没被要求的抽象层、配置项、
"以后可能用得上"的接口。范围锁死，决策放开。

**验证过的决策和踩坑写进 `docs/decisions.md`**，不写进本机记忆目录——
换台机器就丢了，协作者 clone 也看不到。
```

## 2. CLAUDE.md：项目事实

这部分**必须按项目实际填**，照抄空模板等于没写。

```markdown
## 项目简介

一句话说清这个项目是做什么的。

## 永久规范

| 规范 | 要求 |
|------|------|
| ⚠️ API 使用 | 不确定签名/参数/返回值时先查官方文档，不要凭空假设 |
| {{项目特有的硬约束}} | {{比如：颜色间距字号禁止硬编码，必须用 CSS 变量}} |

## 高风险文件

改这些文件前先确认影响范围：

| 文件 | 改前必须检查 |
|------|-------------|
| {{类型定义入口}} | 所有引用该类型的模块 |
| {{数据库 schema}} | 所有查询和 migration |

## 文档路由

| 场景 | 去读 |
|------|------|
| {{某功能}} | `docs/flows/{{xxx}}-flow.md` |
| 调试报错 | `docs/reference/troubleshooting/` |
| 项目为什么这么定 | `docs/decisions.md` |
```

写不出内容的表格整个删掉，别留空壳。

## 3. CLAUDE.md：提交约定（可选）

项目已有提交规范就沿用已有的，别覆盖。没有则：

## 提交约定

未经明确授权不 commit、不 push。

## 4. docs 骨架

**只建马上有东西可放的目录。** 空目录看起来像已经组织好了，比没有更糟。

```
docs/
├── README.md          # 导航，超过 3 个文档才需要
├── decisions.md       # 决策与踩坑，必建
├── flows/             # Mermaid 流程图
│   └── system-overview.md
└── reference/         # 按需长出来，别预建
    └── troubleshooting/
```

`design/` 只在项目有 UI 时建（tokens / themes / ui-patterns）。

流程图用 **Mermaid 文本**写在 markdown 里，不要贴图片——
AI 读图片只能靠猜，读 Mermaid 能精确理解每个分支。
每张流程图后面跟「关键规则」和「排查指南」两节，
AI 才知道不能漏什么、出问题去哪找。

## 5. docs/decisions.md

项目记忆的落地点。保持极简，别做成 ADR 那套重家伙——重了就没人写。

```markdown
# 决策与踩坑

> 验证过的才写进来。猜测、纯咨询和原始对话不写。

## 决策

| 日期 | 决定了什么 | 为什么 | 放弃了什么 |
|------|-----------|--------|-----------|

## 踩坑

| 日期 | 现象 | 根因 | 修法 |
|------|------|------|------|
```

## 6. .claude/limits.json

hook 的阈值。不建也能跑（走默认值），需要调时才建。

```json
{
  "default": 500,
  "byExtension": { ".vue": 400 },
  "maxFilesPerDir": 20,
  "ignore": ["src/generated", "src/legacy"]
}
```

| 字段 | 含义 |
|------|------|
| `default` | 代码文件行数上限 |
| `byExtension` | 按扩展名覆盖上限 |
| `maxFilesPerDir` | 单目录直接子文件数上限 |
| `ignore` | 免检路径前缀（生成物、大型字面量表、暂时动不了的遗留代码） |

## 7. skill 版本戳

装进项目的每个 skill 目录放一个 `.source`，以后才知道装的是哪一版：

```
source: JwSkills
commit: {{装的时候的 git rev-parse --short HEAD}}
installed: {{YYYY-MM-DD}}
```

再次运行 `/init-project` 时对比这个戳，判断要不要提示更新。
