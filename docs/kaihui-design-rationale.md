# Kaihui 设计理念：从手动串联到工作流编排

## 起因

用 AI 处理复杂任务时，经常需要手动告诉它：

> 先站在用户角度想想，再站在产品经理角度看看，然后程序员角度评估下，最后搜一下竞品怎么做的。

每次都要重复这套流程。不同类型的任务有不同的最佳流程，但这些流程只存在于用户脑子里——AI 不知道你的习惯，也不知道什么场景该从哪些角度切入。

Kaihui 要解决的就是这个问题：**把用户脑子里的流程经验固化成可复用的模板**。

## 核心定位：项目经理，不是全栈工程师

设计 kaihui 时最关键的决策是：它到底是什么角色？

最终定位是**项目经理**——分配任务、评判产出、推进流程。它不亲自干活，而是调度其他技能和视角来干活。这个定位决定了整个 skill 的结构：

- 它不需要知道怎么写代码（`/triple-check` 知道）
- 它不需要知道怎么做设计（`/plan-before-code` 知道）
- 它不需要知道怎么选思维方向（`/summon` 知道）
- 它需要知道的是：**什么任务该用什么流程，流程里每步该调谁**

## 模板设计：为什么是这六个

内置的六个模板来自采访中用户描述的真实使用场景：

| 模板 | 来源 |
|------|------|
| 深度分析 | 用户经常要从多个角色角度分析同一个问题 |
| 竞品对标 | 用户会站在竞品用户角度审视自己的产品 |
| 新功能开发 | 从 summon 到 plan 到 triple-check 到 review 的完整链条 |
| Bug 修复 | 用户强调要先复核 Bug 是否真实存在 |
| 代码优化 | 用户习惯搜索最佳实践后再用奥卡姆剃刀简化 |
| 需求评审 | 用户会用乔布斯 Focus 哲学来决定要不要做一个需求 |

这些不是凭空设计的模板，而是从用户实际的工作习惯中提炼出来的。

## 步骤类型：视角、技能、动作、收敛

每个模板的步骤分为四种类型：

- **视角**：切换到某个角色思考（产品经理、程序员、设计师...）
- **技能**：调用已有的 skill（`/summon`、`/triple-check`...）
- **动作**：执行具体操作（联网搜索、检查关联代码...）
- **收敛**：综合所有步骤的产出，输出最终结论

为什么要分类型？因为不同类型的步骤执行方式不同。视角需要角色隔离，技能需要调用对应的 skill 流程，动作需要实际操作，收敛需要处理矛盾。混在一起会让 AI 搞不清每步该怎么做。

## 评判机制：不是走过场

每步执行完必须有评判，这是用户的硬性要求。评判不是打个勾就过，而是要回答：

1. 这步的产出质量够不够？
2. 有什么关键发现？
3. 跟前面步骤的结论有没有矛盾？

这个机制的价值在于**错误阻断**——如果第二步发现问题，不会把错误带到第三步。没有评判的流水线就是传声筒，错误会一路放大到最后。

## 踩过的坑（研究发现）

设计过程中研究了 AI workflow 编排的常见失败模式，总结出四个需要关注的方向：

**角色坍塌**：后面的步骤被前面步骤的措辞带跑。比如第一步站在用户角度说"这个功能很重要"，第二步站在程序员角度时本该冷静评估成本，但被第一步的情绪带着走了。解法是每步明确隔离角色。

**错误放大**：第 N 步的错误被第 N+1 步当成事实。这就是为什么评判步骤不能跳过——它是防火墙。

**输出膨胀**：每步都输出一大段，到后面上下文爆炸，AI 开始忘记前面说了什么。解法是每步产出要结构化、精炼，后续步骤引用结论而非复述过程。

**矛盾无收敛**：不同角度给出相反建议，最后没有人做裁决。这就是为什么最后一步必须是"收敛"——明确处理矛盾，不能假装没看到。

## 模板的可扩展性

内置模板只是起点。用户在使用过程中会发现新的流程模式，kaihui 支持：

- AI 根据任务现场组合临时 workflow
- 用户满意后保存为新模板
- 随时编辑已有模板

这个设计的思路是：**模板应该从实践中生长出来，不是提前设计好的**。用得多了，模板库自然会越来越贴合用户的工作习惯。

## 与现有技能的关系

Kaihui 是其他技能的上游编排器，不是替代品：

```
kaihui（编排）
  ├── summon（定方向）
  ├── plan-before-code（做设计）
  ├── triple-check（高质量实现）
  └── code-review（最终审查）
```

它们之间的关系就像公司里的组织架构——kaihui 是项目经理，其他技能是各职能部门的专家。项目经理不需要比每个专家都懂，但需要知道什么时候该找谁、按什么顺序推进。

## 一句话总结

Kaihui 把"用户脑子里的流程经验"变成了"AI 可以自动执行的 workflow 模板"。

开会不是目的，高效交付才是。
