# CLAUDE.md 审查标准

> 作者：Joey Liu
> 日期：2026-04-09

---

审查 CLAUDE.md 里每一句话，只问一个问题：

**这句话如果不写，我会做出错误的假设或者找不到东西吗？**

能答"是"的留下，不能的删掉。

---

## 为什么只需要一条标准

CLAUDE.md 的职责不是教 AI 做好 AI，而是告诉 AI 它否则不会知道的事。

这条问题精确切中了三类噪音：

**噪音一：AI 已知的通用知识**
AI 本来就知道"函数要命名清晰"、"提交信息要有意义"——写了也是废话，占用上下文窗口，稀释真正重要的信息。

**噪音二：自我安慰式的补充**
"注意代码质量"、"保持一致性"——这类话不写也不会出错，写了等于没写，只让 CLAUDE.md 看起来更厚实。

**噪音三：信息已有归属**
有些信息已经在别的地方定义好了，AI 运行时本来就能读到。重复一遍不是补充，是干扰。

典型例子：每个 skill 的触发条件已经写在 skill 定义里（Claude Code 启动时会作为 system-reminder 加载），在 CLAUDE.md 里再列一遍"summon 用于召唤词"是冗余——AI 不需要你告诉它，它自己会读到。

一条标准胜过十条原则，因为它是可操作的：逐句问，答不上来就删。

---

## 反面例子

经不起这个问题的内容：

```
- 代码要写注释
- 不要引入没必要的依赖
- 变量命名要清晰
- 提交前先测试
```

问：这些不写，我会做出错误的假设吗？不会——这些是常识。

```
- 保持代码整洁
- 遵循最佳实践
- 注意性能
```

问：这些不写，我会找不到东西吗？不会——这些太模糊，找不到任何东西。

```
## Skill 用途

- summon：召唤词词典，用于给 AI 定方向
- triple-check：三遍自纠工作流
- code-review：系统代码审查
```

问：这些不写，我会找不到东西吗？不会——每个 skill 的描述和触发条件已经写在 skill 定义里，Claude Code 启动时直接加载，这里重复一遍只是噪音。

---

## 正面例子

能通过这个问题的内容：

```
## 双 Skills 文件夹

修改任何 skill 时必须同步更新两个目录：
- `.claude/skills/`：工作副本，Claude Code 直接加载
- `skills/`：发布副本，供用户 clone 后使用
```

问：不写这个，我会做出错误的假设吗？**会**——我可能只改一个目录，造成两边不一致。

```
## 文档

| `docs/guides/skill-design-philosophy.md` | Skill 设计哲学：方向而非枷锁 |
```

问：不写这个，我会找不到东西吗？**可能会**——如果不知道这个文件存在，设计时就不会去参考它。

---

## 与 Skill 设计哲学的关系

这条标准和 [skill-design-philosophy.md](skill-design-philosophy.md) 里的核心原则是同一枚硬币的两面：

- Skill 设计哲学说的是：**只写方向，不写 AI 已知的规则**
- CLAUDE.md 审查标准说的是：**只写不写会出错的东西**

都在问同一个问题：这段文字是在给 AI 提供真正缺失的信息，还是在自我感动？
